# Internationalization Rule

## Hard Rules

1. **No user-facing string literals in components.** Use the project's i18n library with keys (`t('orders.empty')`). Keys are English, namespaced by feature.
2. **Never concatenate translated fragments.** Use interpolation and ICU plurals (`t('orders.count', { count })`) so word order and plurals work in every language.
3. **Format dates, numbers, and currency with `Intl`** (`Intl.DateTimeFormat`, `Intl.NumberFormat`) using the active locale — never manual formatting.
4. **Set `<html lang>` and `dir`** from the active locale and update them on change.
5. **Layouts must tolerate text expansion and RTL:** use logical CSS properties (`margin-inline-start`, `padding-inline`) instead of left/right.
6. **Do not store translated text in state or the cache;** store keys/codes and translate at render.
7. **Missing keys fail loudly in dev/CI** (type-checked keys or a lint check), and fall back to the default locale in production.
8. **Load locale bundles lazily** per language/namespace.

## Why

Hard-coded strings and hand-built plurals are the most expensive thing to retrofit. Keeping translation keys, `Intl` formatting, and logical CSS from day one makes localization a content task, not a refactor.
